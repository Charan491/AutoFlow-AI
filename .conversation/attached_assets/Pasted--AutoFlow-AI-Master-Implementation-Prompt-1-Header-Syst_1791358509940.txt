**1. Header & System Persona Role**
You are an Expert AI Systems Architect, Principal Full-Stack Developer, and UI/UX Specialist. You have deep expertise in building enterprise-grade, highly scalable web applications using React.js (Vite), Node.js with Express.js, PostgreSQL, Tailwind CSS, and advanced AI integration using the official `@google/genai` SDK. Your task is to build a complete, production-ready application called **AutoFlow AI** based on the exhaustive specifications provided below. You must write the actual, fully functional code, avoiding placeholders, "todo" comments, or mock implementations (except where explicitly noted for initial database seeding). Execute this build with a focus on security, performance, responsive design, and robust error handling.

**2. Core Mission Directive**
Build **AutoFlow AI**, an intelligent workflow orchestration platform that converts unstructured organizational requests (e.g., "The printer in accounting is broken") into structured, automated, end-to-end workflows. The system must autonomously parse requests using AI, determine the correct workflow category, assign tasks to appropriate roles, track SLAs (Service Level Agreements), monitor bottlenecks, and provide real-time analytics.

**3. Product Goal**
To eliminate the manual overhead of managing routine internal requests (leave, IT, maintenance, procurement, document approval) by shifting from a traditional human-routed model to an AI-orchestrated model. The platform must understand intent, extract metadata, assign responsibility, and monitor progress until resolution, drastically reducing processing time and human error.

**4. Mandatory Features**

* **AI Request Understanding:** Natural language processing of user requests to extract intent, department, urgency, and required actions.
* **Intelligent Workflow Generation & Routing:** Dynamic creation of multi-step task workflows based on the AI's classification (e.g., IT vs. Finance workflows).
* **Smart Task Assignment:** Automated assignment of tasks based on role, department, and calculated priority.
* **Risk-Based Approval Chains:** Low-risk items auto-approved; high-risk items escalated to management.
* **SLA Monitoring & Automatic Follow-ups:** Tracking of task deadlines with visual indicators of SLA status.
* **Bottleneck Analytics Dashboard:** Real-time visibility into system health, average processing times, and department loads.

**5. Technology Requirements**

* **Frontend:** React.js (Vite), Tailwind CSS, Lucide React (for icons), Recharts (for dashboard analytics), React Router DOM.
* **Backend:** Node.js, Express.js.
* **Database:** Replit Postgres (standard PostgreSQL). Use the `pg` package for connections.
* **AI Integration:** `@google/genai` SDK. Must use `gemini-2.5-flash` model.
* **Validation:** Zod (for both API request validation and strict AI structured output validation).
* **State Management:** React Context API or Zustand.

**6. Application Pages (Routes)**

* `/` (Dashboard): Main analytics overview, SLA violations, workload by department, and quick stats.
* `/requests/new` (Submit Request): Natural language input form (textarea) for employees to submit unstructured requests.
* `/requests` (My Requests): List view of the user's submitted requests and their current workflow status.
* `/tasks` (Task Inbox): Kanban board or list view of tasks assigned to the current user/role requiring action.
* `/requests/:id` (Request Details): Deep dive into a specific request, showing the AI-extracted data, the workflow timeline, and current bottleneck/status.

**7. User Flow**

1. **Submission:** User enters an unstructured problem/request via the `/requests/new` interface.
2. **Processing (Background):** The backend receives the text, sends it to Gemini via the structured output prompt, and receives a validated JSON payload containing the classification, priority, and required workflow steps.
3. **Orchestration:** Backend writes the request to the database, generates the associated `tasks` based on the AI's workflow steps, and assigns them.
4. **Action:** Assigned users (e.g., IT Technician, Manager) view the `/tasks` route, update statuses (Pending -> In Progress -> Completed).
5. **Analytics:** Management views the `/` dashboard to monitor SLA compliance, task volume, and average resolution times.

**8. Target Domains & Categorization**
The AI must strictly categorize incoming unstructured text into one of the following domains:

* `IT_SUPPORT`: Hardware/software issues, access requests.
* `MAINTENANCE`: Facility issues, broken equipment.
* `PROCUREMENT`: Purchase requests, office supplies.
* `HR_LEAVE`: Time off, policy inquiries.
* `DOCUMENT_APPROVAL`: Contracts, internal memos.

**9. Form & Advisory Configuration**
The submission interface should primarily feature a single, prominent Textarea ("Describe your request or issue in detail"). It should also allow optional file attachments (simulated/mocked for this build as URL inputs) and a "Submit to AI Orchestrator" button. The UI must show a loading state with steps ("Analyzing intent...", "Generating workflow...", "Assigning tasks...") while waiting for the backend API.

**10. Database Schema (Production SQL for PostgreSQL)**
Execute the following schema to establish the relational structure:

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    full_name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    role VARCHAR(50) NOT NULL, -- e.g., 'EMPLOYEE', 'MANAGER', 'TECHNICIAN', 'ADMIN'
    department VARCHAR(100) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE requests (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    requester_id UUID REFERENCES users(id),
    raw_text TEXT NOT NULL,
    category VARCHAR(50) NOT NULL,
    priority VARCHAR(20) NOT NULL, -- 'LOW', 'MEDIUM', 'HIGH', 'CRITICAL'
    risk_level VARCHAR(20) NOT NULL, -- 'LOW', 'MEDIUM', 'HIGH'
    extracted_entities JSONB NOT NULL DEFAULT '{}'::jsonb,
    status VARCHAR(50) NOT NULL DEFAULT 'IN_PROGRESS', -- 'IN_PROGRESS', 'RESOLVED', 'REJECTED'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    resolved_at TIMESTAMP WITH TIME ZONE
);

CREATE TABLE tasks (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    request_id UUID REFERENCES requests(id) ON DELETE CASCADE,
    assigned_role VARCHAR(50) NOT NULL,
    assigned_department VARCHAR(100) NOT NULL,
    assigned_user_id UUID REFERENCES users(id), -- Nullable if pooled to a department/role initially
    step_order INTEGER NOT NULL,
    title VARCHAR(255) NOT NULL,
    description TEXT,
    status VARCHAR(50) NOT NULL DEFAULT 'PENDING', -- 'PENDING', 'IN_PROGRESS', 'COMPLETED', 'ESCALATED'
    sla_deadline TIMESTAMP WITH TIME ZONE NOT NULL,
    completed_at TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE workflow_logs (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    request_id UUID REFERENCES requests(id) ON DELETE CASCADE,
    action VARCHAR(255) NOT NULL,
    actor_id UUID REFERENCES users(id), -- System is NULL
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

```

**11. Row Level Security (RLS) / Data Isolation Rules**
Implement robust API-level data isolation (since standard Express/pg setup is used):

* `EMPLOYEE` role can only GET `requests` where `requester_id` matches their own ID.
* `TECHNICIAN` / `MANAGER` can GET `tasks` assigned to their specific `assigned_department` or `assigned_role`.
* `ADMIN` can GET all data across all tables.
* All backend routes must accept a `x-user-id` and `x-user-role` header (to mock authentication for this prototype) and enforce these rules before returning data.

**12. Backend API Routes**
Implement the following RESTful endpoints in Express:

* `POST /api/requests`: Accepts `{ rawText }`. Uses `x-user-id` header for the requester. Calls Gemini to parse, inserts Request, inserts Tasks, inserts initial Workflow Logs. Returns the created Request object.
* `GET /api/requests`: Returns requests based on isolation rules. Support query params for status filtering.
* `GET /api/requests/:id`: Returns request details, joined with tasks and logs.
* `GET /api/tasks`: Returns tasks assigned to the requesting user/role.
* `PATCH /api/tasks/:id/status`: Updates task status (e.g., COMPLETED). If the task is completed, automatically checks if the next task in `step_order` should be activated. If it's the final task, marks the `Request` as RESOLVED. Creates a `workflow_log`.
* `GET /api/analytics`: Returns aggregated data for the dashboard (total requests, SLA breach counts, average completion time by department, open tasks by role).

**15. Detailed AI Prompts (with required JSON Schemas)**
**Endpoint Prompt Structure:**

```javascript
const response = await ai.models.generateContent({
    model: 'gemini-2.5-flash',
    contents: `Analyze the following employee request and orchestrate the workflow: "${rawText}"`,
    config: {
        systemInstruction: "You are the AutoFlow AI Orchestrator...", // From Section 14
        responseMimeType: "application/json",
        responseSchema: {
            type: "OBJECT",
            properties: {
                category: { type: "STRING", enum: ["IT_SUPPORT", "MAINTENANCE", "PROCUREMENT", "HR_LEAVE", "DOCUMENT_APPROVAL"] },
                priority: { type: "STRING", enum: ["LOW", "MEDIUM", "HIGH", "CRITICAL"] },

                    type: "OBJECT", 
                    description: "Key-value pairs of extracted data (e.g., item: 'printer', location: 'accounts')" 
                },
                workflow_tasks: {
                    type: "ARRAY",
                    description: "Sequential tasks required to complete this request.",
                    items: {
                        type: "OBJECT",
                        properties: {
                            step_order: { type: "INTEGER" },
                            title: { type: "STRING" },
                            description: { type: "STRING" },
                            assigned_role: { type: "STRING" },
                            assigned_department: { type: "STRING" },
                            estimated_hours_to_complete: { type: "INTEGER" }
                        },
                        required: ["step_order", "title", "description", "assigned_role", "assigned_department", "estimated_hours_to_complete"]
                    }
                }
            },
            required: ["category", "priority", "risk_level", "extracted_entities", "workflow_tasks"]
        }
    }
});

```
